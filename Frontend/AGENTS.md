# Foveated LiDAR Mapping Dashboard Architecture

This file documents the current state and architecture of the Foveated LiDAR Mapping Dashboard, designed to help future AI agents understand the system. **All significant changes must be documented here.**

---

## Overview

A web-based Next.js dashboard visualizing a 3D LiDAR point cloud dataset using a foveated mapping approach — mimicking human vision by rendering the vehicle's immediate vicinity at high detail and distant areas at lower resolution, saving memory and processing.

**Problem Statement Goals (PS):**
1. Terrain Analysis — distinguish drivable vs non-drivable surfaces
2. Object Detection — classify static/dynamic obstacles across varying distances
3. Adaptive Spatial Representation — non-uniform variable-resolution 2.5D grid

---

## Dataset

**File:** `public/data/autonomous_driving_demo_data.json`

**Structure:**
- `frames[]` (30 frames): per-frame vehicle state, detected_objects, planned_path, metrics
- `static_environment.lidar_points[]` (50,000 pts): { position, intensity, classification }
- `static_environment.map_cells[]` (5,331 cells): variable-size foveated cells with zone field

**LiDAR classifications:** road, curb, building, vegetation, pothole, cattle

**Object types:** pedestrian, bus, truck, auto-rickshaw, bicycle, road barrier, cattle, pothole

**Coordinate system:** X=forward, Y=lateral, Z=height. Three.js mapping: d2t(p) = [p[0], p[2], -p[1]]

**Spatial bounds:** X: -10 to 100, Y: -15 to 15, Z: -0.17 to 8

### Foveated map_cells Zone Structure (REGENERATED)

map_cells were regenerated by scratch/regenerate-map-cells.js to have true variable sizes:

| Zone | Distance from ego | Cell size | Count |
|------|-------------------|-----------|-------|
| near | 0-10 m | 0.5 m | ~1,257 |
| mid  | 10-40 m | 1.5 m | ~2,088 |
| far  | 40-100 m | 3.0 m | ~1,986 |
| Total | | | ~5,331 |
| Uniform 0.5m equivalent | 200mx30m | 0.5m | 24,000 |
| Memory savings | | | ~77.8% |

Each cell has: { center, size, elevation, terrain, semantic, occupancy, zone }

## Architecture: Core Grid Engine

### app/lib/foveatedGrid.ts [NEW]

The Variable Resolution Grid Engine -- the mathematical core of the PS solution.

**Key exports:**
- buildFoveatedGrid(lidarPoints, egoX, egoY): FoveatedGridResult
  - PROJECTS raw LiDAR 3D points into variable-size 2D cells (PS requirement)
  - Snaps each point to its zone cell size (near=0.5m, mid=1.5m, far=3.0m)
  - Cell elevation = max Z of all points inside that cell
  - Cell semantic = dominant classification (majority vote)
  - Computes memorySavingsPct vs hypothetical uniform 0.5m grid
- SEMANTIC_COLORS_HEX -- semantic class to hex color
- OBJ_TYPE_COLORS -- object type to hex color (used by ALL panels for consistency)
- STATIC_OBJECT_TYPES / DYNAMIC_OBJECT_TYPES -- PS classification sets
- getObjectClass(type) -- returns 'static' | 'dynamic' | 'unknown'
- getSemanticColor(semantic), getObjColor(type), zoneAlpha(zone)
- NEAR_RADIUS=10, MID_RADIUS=40, FAR_RADIUS=100

IMPORTANT: All components MUST import colors from foveatedGrid.ts. Never define colors locally.

Object classification:
- STATIC: road barrier, pothole (drawn with dashed border in 2D map)
- DYNAMIC: pedestrian, bus, truck, auto-rickshaw, bicycle, cattle (solid border, pulsing in 3D)

## Components (The 4 Panels)

### Panel 1 — Live LiDAR Point Cloud (app/components/LidarScene.tsx)
- Type: 3D WebGL (React Three Fiber / Three.js)
- Features:
  - 50k LiDAR points colored by classification via custom GLSL shaders
  - Distance-based foveation: near=full bright, mid=dimmed, far=very dim
  - [NEW] DetectedObjects3D: wireframe EdgesGeometry boxes per detected_objects each frame
  - Object boxes colored by OBJ_TYPE_COLORS, opacity proportional to confidence
  - Risk-proportional pulse animation (risk > 0.4 triggers sin-wave scaling)
  - GLB car model (/car.glb) with box fallback. Camera follows car via lerp.

### Panel 2 -- Foveated 2.5D Semantic Map (app/components/SemanticMap2D.tsx)
- Type: 2D Canvas (Top-Down View)
- Features:
  - Calls buildFoveatedGrid(lidarPoints, egoX, egoY) -- true 3D point projection
  - Near-zone cells (0.5m): raw LiDAR points snapped to 0.5m bins, max-Z elevation, majority-vote semantic
  - Mid/far cells aggregated at 1.5m/3.0m resolution
  - Zone alpha: near=1.0, mid=0.65, far=0.35
  - [NEW] Dashed concentric zone rings at 10m and 40m
  - [NEW] detected_objects overlay with STATIC [S] vs DYNAMIC [D] classification badge
    - Static objects: dashed border (road barrier, pothole)
    - Dynamic objects: solid border + [D] label (pedestrian, bus, bicycle, etc.)
  - [NEW] Memory savings HUD badge (top-left): '77.8% memory vs uniform 0.5m'
  - [NEW] Dual legend (top-right): terrain semantics + static/dynamic object types
  - View radius: 55m. Canvas rotated so forward (X) points up.

### Panel 3 — 3D Elevation Map (app/components/ElevationMap3D.tsx)
- Type: 3D WebGL (React Three Fiber / Three.js)
- Features:
  - Points colored by Z-height (blue to green to red gradient)
  - [NEW] ElevationObjects: wireframe boxes per detected_objects in each frame
  - Camera auto-rotates and follows car via lerp

### Panel 4 — Elevation Slice + Accuracy Chart (app/components/ElevationSlice.tsx)
- Type: 2D Canvas with tab switcher
- Tab 1 (elevation slice):
  - Front cross-section of LiDAR points within +/-2m of ego X
  - Height gradient coloring, axis grid, tick labels
  - [NEW] Detected object cross-sections for objects near the slice window
  - Ego vehicle bounding box; pothole alert box; height gradient legend
- Tab 2 (accuracy chart): renders AccuracyChart component

### AccuracyChart (app/components/AccuracyChart.tsx) [NEW]
- Type: 2D Canvas
- Aggregates all 30 frames detected_objects.confidence by zone (near/mid/far)
- Grouped bar chart proving "high accuracy across varying distances" (PS requirement)
- Static (aggregated across all frames, no per-frame update)

### MetricsHUD (app/components/MetricsHUD.tsx) [REWIRED]
- Type: React overlay, positioned absolute bottom-left of Panel 1
- Props: metrics (per-frame FrameMetrics), fps, memorySavingsPct, frameIdx, totalFrames
- Shows: fps, latency_ms, objects_detected, collision_risk, mem_savings, perception_latency
- Bar indicators with risk-color coding (green/amber/red)

### LidarViewer (app/components/LidarViewer.tsx) [REWRITTEN]
- Root orchestrator component (dynamically imported in /lidar-viewer/page.tsx)
- Manages: data fetching, frameIdx state, play/pause, FPS counter (rAF-based)
- [RESTORED] 2x2 grid with all 4 panels mounted
- Header shows: fps, frame count, speed, object count
- Calls buildFoveatedGrid() each render for live memory savings metric
